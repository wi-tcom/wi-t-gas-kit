# 見本：CSV照合

[English](README.en.md)

「会計」シートの表と、取り込んだ CSV（銀行の入金明細など）を **請求番号で突き合わせ**、
一致・不一致・片方だけ を「照合結果」シートに出す見本です。スプレッドシートのメニューから動かします。

- 版：`1.0.0`（`main.js` の `CSV_RECONCILE_VERSION`。変更の記録は [CHANGELOG.md](CHANGELOG.md)）
- 使う部品：`version.js`・`lock.js`・`runlog.js`・`notify.js`・`guard.js`・`reconcile.js`・`handover.js`・`settings.js`・`migrate.js`（`parts.json`）
- 照合は `WitGas.reconcile`、実行は `WitGas.guard` で包んでいます。
- 実行のたびに「実行記録」シートへ 1 行（件数だけ）残し、失敗したらメールで知らせます。
- データはすべて架空です。

## この見本の段階

| 段階 | この見本でできること |
|------|----------------------|
| 1. 動く | メニューの「照合する」で照合する。二重に動かない・実行記録・失敗の通知（`WitGas.guard`） |
| 2. 任せられる | 照合そのものが「元のデータとの突き合わせ」。**定時に自動では動かない**（CSV をシートに取り込むのが人の作業のため） |
| 3. 変えられる | シート名・呼び名・キー・比べる列・列の対応・通知先を「設定」シートで変えられる。引き継ぎ書と版上げの手順がある |

### 次の段階で足せること

- 定時に自動で照合する（CSV を Drive やメールの添付から読む形に変え、時間主導型のトリガーで動かす。下の「Drive やメールから CSV を読む場合」）。
- 不一致があったときに、担当者へ件数だけをメールで知らせる。
- 照合結果を日ごとに台帳へ残し、前回からの変化を見られるようにする。
- 不一致を見つけたときの確かめ方の手引きと、問い合わせのひな形を付ける。

## シート

| シート | 中身 | 誰が書くか |
|--------|------|------------|
| 会計 | 手元の表（1 行目が見出し。請求番号・金額・入金日 など） | 先方 |
| CSV貼り付け | 取り込んだ CSV（1 行目が見出し。請求番号・入金額・入金日 など） | 先方（取り込み） |
| 照合結果 | 区分ごとの件数と明細 | このスクリプト（毎回書き直す） |
| 実行記録 | 1 実行 1 行（開始・終了・結果・件数・件数の内訳） | このスクリプト |
| 設定 | 先方ごとに変える値（下の「設定」） | 「設定と表を用意する」が作り、先方が値を変える |
| 引き継ぎ書 | 版・権限・設定値・止め方 | 「引き継ぎ書を作る」 |

## 入れ方

### スクリプトエディタに貼る

1. 照合に使うスプレッドシートで「拡張機能 → Apps Script」を開く。
2. 次のファイルを、同じ名前で作って中身を貼る（`.gs` になってかまいません）。
   - リポジトリの `src/` から、`parts.json` に書いてある 9 つ
   - この見本から：`main.js`
3. 「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` をこの見本のものに置き換える。
4. スプレッドシートを開き直すと、メニューに「照合」が出る。「照合 → 設定と表を用意する」を実行する。
5. 「設定」シートの「失敗の通知先」を、失敗を知らせる先のアドレスに変える。「照合 → 点検する」で、見本のアドレスのままでないことを確かめられる。

### clasp で送る

```bash
cd examples/csv-reconcile
echo '{"scriptId":"（スプレッドシートに付いたスクリプトの ID）"}' > .clasp.json
cd ../..
npm run example:build -- csv-reconcile
cd dist/csv-reconcile
npx @google/clasp push
```

`npm run example:build` は、この見本の `appsscript.json`・`main.js` と、`parts.json` に書いた部品を `dist/csv-reconcile/` にまとめます。
`.clasp.json` はコミットしません。

## 使い方

### 見本のデータで試す

メニュー「照合 → 見本のデータを入れる」のあと、「照合 → 照合する」。
「会計」か「CSV貼り付け」にデータがあるときは、見本のデータは入れません（消さずに止めます）。

結果は次のとおりになります（`test/examples/csv-reconcile.test.js` で確かめています）。

```
一致 2 / 不一致 2 / 会計だけ 1 / 銀行だけ 1 / キー重複 0 / キーなし 0
```

### 本番の CSV を取り込む

1. 「CSV貼り付け」シートを選ぶ。
2. 「ファイル → インポート → アップロード」で CSV を選ぶ。
3. 「インポート場所」は **現在のシートを置換する** にする。
4. **「テキストを数値、日付、数式に変換する」をオフ** にする。
   オンのままだと、`001` のような番号の先頭の 0 が落ちたり、`=` で始まる値が式になったりします。
   金額（`"1,000"`）や日付（`2026/1/5`）は、文字のままでも照合のときにそろえます。
5. メニュー「照合 → 照合する」。

文字化けする場合は、CSV を UTF-8 で保存し直してから取り込んでください。

## 設定（「設定」シート）

| 項目 | 既定の値 | 内容 |
|------|----------|------|
| 会計のシート／CSV のシート | 会計／CSV貼り付け | 照合する 2 つのシート |
| 照合結果のシート／実行記録のシート | 照合結果／実行記録 | 書き出すシート |
| 呼び名（会計）／呼び名（CSV） | 会計／銀行 | 結果に出る呼び名（「会計だけ」「銀行の値」など） |
| キーの列 | 請求番号 | 会計の見出しの名前。複数ならカンマで区切る |
| 比べる列 | 金額, 入金日 | 会計の見出しの名前をカンマで区切る |
| 列の対応 | 金額=入金額 | 名前が違う列だけ「会計の列名=CSV の列名」をカンマで区切る |
| 数の列 | 金額 | "110,000" と 110000 を同じにする列 |
| 日付の列 | 入金日 | シートの日付と "2026/1/5" を同じ日にする列 |
| 全角と半角を区別しない | はい | `Ａ０１` と `A01` を同じにする |
| 失敗の通知先 | ops@example.com | **必ず変える** |

- 値がおかしいとき（列の対応の書き方が違う、数の列が比べる列にない、通知先がメールアドレスでない、など）は、どの項目かを画面で知らせて、何もしません。
- 設定シートは、コードを入れ替えても消えません。照合の細かい決まりは、リポジトリの README の `WitGas.reconcile` を見てください。

## 結果の見方

「照合結果」シートの上に区分ごとの件数、その下に明細が出ます。

| 区分 | 意味 | よくある原因 |
|------|------|--------------|
| 一致 | 比べた列がすべて同じ | — |
| 不一致 | 請求番号は両方にあるが、金額か入金日が違う（違う列ごとに 1 行） | 入金額の誤り、振込手数料の差し引き、入金日のずれ |
| 会計だけ | 会計にあって CSV にない | 未入金 |
| 銀行だけ | CSV にあって会計にない | 会計への登録漏れ、請求番号の書き間違い |
| キー重複 | 同じ請求番号が 2 行以上ある | 二重登録、分割入金 |
| キーなし | 請求番号が空 | 番号の書き忘れ |

## 権限

| 権限 | 理由 |
|------|------|
| `https://www.googleapis.com/auth/spreadsheets.currentonly` | このスプレッドシートだけを読み書きする（ほかのスプレッドシートには触らない） |
| `https://www.googleapis.com/auth/script.container.ui` | メニューと、入力が足りないときの知らせを出す |
| `https://www.googleapis.com/auth/script.send_mail` | 失敗をメールで知らせる |

トリガーを作らないので、`script.scriptapp` は使いません。
`spreadsheets.currentonly` で足りることは、まだ GAS 上で確かめていません（`docs/manual-check.md` の E1）。足りなければ `spreadsheets` に変えます。

## 業務データの扱い

- 「照合結果」シートには、照合のために請求番号・金額・日付が入ります。このスプレッドシートの共有の範囲に気をつけてください。
- 「実行記録」とメールに書くのは、件数とエラー種別だけです。
- 失敗したときの詳しいエラーは、Apps Script の「実行数」画面で確認します。

## すでに `onOpen` がある場合

スクリプトに `onOpen` がすでにあると、どちらかが上書きされます。この見本の `onOpen` の中身（メニューを足す部分）を、今ある `onOpen` に移してください。

## 失敗したとき

| 起きたこと | 画面 | 実行記録 | メール |
|------------|------|----------|--------|
| 設定をまだ用意していない（版上げの途中を含む） | 「設定と表を用意する」を実行するよう知らせる | 残さない | 送らない |
| 設定の値がおかしい | どの項目かを知らせる | 残さない | 送らない（通知先も設定のため） |
| 「会計」か「CSV貼り付け」が空 | 「…見出しのある表を入れてから実行してください。」 | 残さない | 送らない |
| 見出しに、照合に使う列がない（CSV の形式が違う） | どのシートの何がないか（例：「「CSV貼り付け」の見出し（1 行目）に「入金額」がありません。…」） | 失敗（`CsvFormatError`） | 送る |
| それ以外の失敗 | Apps Script のエラー表示 | 失敗（エラー種別） | 送る |

それ以外の失敗は、Apps Script の「実行数」画面に失敗として残り、詳しいエラーはそこで読めます。

## 実行記録のタイムゾーン

新しく作ったスプレッドシートは、設定画面に「東京」と出ていても、太平洋時間で保存されていることがあります（リポジトリの README の `WitGas.runlog` を参照）。
この見本は、「実行記録」シートを初めて作るときだけ、このスプレッドシートのタイムゾーンをスクリプト（Asia/Tokyo）に合わせます（`matchTimeZone: true`）。

なお 2026-11-26 の実機確認では、「拡張機能 → Apps Script」でスクリプトを付けた時点で、このスプレッドシートのタイムゾーンは `Asia/Tokyo` に変わっていました。そのため `matchTimeZone` が働く場面にはなりませんでしたが、念のためオンのままにしています。

## 止め方

- トリガーは作りません。メニューから動かしたときだけ動きます。スクリプトのプロパティには、スキーマの版（`WitGas.schema:csvReconcile`）だけを置きます。
- 引き継ぎ書には、トリガーの一覧を出しません（トリガーを使わないので、一覧を読む権限 `script.scriptapp` を持たないため）。
- 使わなくなったら、`main.js` の `onOpen` を消せばメニューが出なくなります。
- 「照合結果」と「実行記録」のシートは、消してもかまいません（次に照合したときに作り直します）。

## 版上げのしかた

1. **事前**：スプレッドシートをコピーする（「ファイル → コピーを作成」）。スクリプトもいっしょにコピーされます。
2. **入れ替え**：新しい版の `main.js` と、`parts.json` の部品を貼り直す（clasp なら `npm run example:build -- csv-reconcile` のあと `clasp push`）。`appsscript.json` も新しい版のものにする。
3. **実行**：メニュー「照合 → 設定と表を用意する」。まだ動いていない移行の段だけが動きます。何度動かしても結果は変わらず、設定シートの値は残ります。
4. **点検**：「点検する」で問題がないことを確かめ、「引き継ぎ書を作る」で版が新しくなったことを確かめる。
5. **戻し方**：うまくいかないときは、1 で作ったコピーを使う（元のスプレッドシートは使うのをやめる）。

### 前の形（版番号なし）から 1.0.0 に上げるとき

前の形は、設定を `main.js` の `CSV_RECONCILE` に書いていました。1.0.0 では「設定」シートに移したので、次のようにします。

1. 入れ替える前に、今の `main.js` の `CSV_RECONCILE` の値（特に `notifyTo`。`labels`・`compare` を変えていればそれも）を控える。
2. 上の 1〜3 のとおりに入れ替えて「設定と表を用意する」を実行する。「設定」シートが既定の値でできます。
3. 控えた値を「設定」シートに入れ直す（`notifyTo` は「失敗の通知先」、`compare.columnMap` は「列の対応」など）。
4. 「点検する」。通知先が見本のアドレスのままなら、ここで知らせが出ます。

会計・CSV貼り付け・照合結果・実行記録のシートは、そのまま使えます。

## Drive やメールから CSV を読む場合

この見本は、権限を増やさないために「シートに取り込む」形にしています。
Drive に置かれた CSV やメールの添付から直接読む場合は、`runCsvReconcile` の `right` を次のように差し替えます。
**どちらも GAS 上では確かめていません。** 使うときは権限を足し、実機で確かめてから納品してください。

```js
// Drive のファイル
var blob = DriveApp.getFileById('（CSV のファイル ID）').getBlob();
var right = Utilities.parseCsv(blob.getDataAsString('UTF-8'));

// メールの添付
var thread = GmailApp.search('from:（送り元） has:attachment filename:csv newer_than:7d', 0, 1)[0];
var att = thread.getMessages().pop().getAttachments()[0];
var right = Utilities.parseCsv(att.getDataAsString('UTF-8'));
```

| 読み込み元 | 足す権限（見込み） | 気をつけること |
|------------|--------------------|----------------|
| Drive | `https://www.googleapis.com/auth/drive.readonly` | Drive の全ファイルを読める権限になる |
| メール | `https://mail.google.com/` | `GmailApp` は、読むだけでもメール全体（送信・削除を含む）の権限を求める見込み。先方への説明が要る |

文字コードが Shift_JIS の CSV は `getDataAsString('Shift_JIS')` にします（これも GAS 上では確かめていません）。
