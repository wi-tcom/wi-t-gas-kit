# 見本：帳票 PDF の一括作成（pdf-batch）

[English](README.en.md)

「明細」シートの 1 行を 1 枚の「お見積書」にして PDF を作り、スクリプトが作ったドライブのフォルダにまとめる見本です。スプレッドシートのメニューから動かします。

- 版：`1.0.0`（`main.js` の `PDF_BATCH_VERSION`。変更の記録は [CHANGELOG.md](CHANGELOG.md)）
- 使う部品：`version.js`・`lock.js`・`resume.js`・`runlog.js`・`notify.js`・`guard.js`・`handover.js`・`settings.js`・`migrate.js`（`parts.json`）
- データはすべて架空です。帳票は「お見積書」の体裁で、「請求書」とは名乗りません（税の要件を満たすかは、この見本の範囲外です）。

## この見本の段階

| 段階 | この見本でできること |
|------|----------------------|
| 1. 動く | メニューの「PDF を作る」で、明細から PDF を作る。二重に動かない・実行記録・失敗の通知（`WitGas.guard`） |
| 2. 任せられる | 件数が多くても区切って続ける（`WitGas.resume`）。**定時に自動で動かすことと、作った枚数を明細と突き合わせることは、まだ入っていない** |
| 3. 変えられる | 題・発行元・列名・フォルダ名・上限・通知先を「設定」シートで変えられる。引き継ぎ書と版上げの手順がある |

### 次の段階で足せること

- 定時に自動で作る（毎晩など。時間主導型のトリガーを張る関数と外す関数）。
- 作った枚数を明細と突き合わせる（`WitGas.reconcile` で、明細の見積番号と作成記録の見積番号を照合する）。
- 前後の作業とつなぐ：作った PDF を宛先にメールで送る、送った記録を台帳に残す。
- 1 枚に品名を何行も載せる（明細を見積番号ごとにまとめる）。

## シート

| シート | 中身 | 誰が書くか |
|--------|------|------------|
| 設定 | 先方ごとに変える値（下の「設定」） | 「設定と表を用意する」が作り、先方が値を変える |
| 明細 | 1 行が 1 枚の帳票（見積番号・宛先・品名・数量・単価・日付） | 先方 |
| 作成記録 | 作った帳票の見積番号・作成日時・ファイル ID・ファイル名 | このスクリプト |
| 実行記録 | 1 実行 1 行（件数と内訳だけ） | このスクリプト |
| 引き継ぎ書 | 版・トリガー・権限・設定値・止め方 | 「引き継ぎ書を作る」 |

## 入れ方

### スクリプトエディタに貼る

1. 帳票を作るスプレッドシートで「拡張機能 → Apps Script」を開く。
2. 次のファイルを、同じ名前で作って中身を貼る（`.gs` になってかまいません）。
   - リポジトリの `src/` から、`parts.json` に書いてある 9 つ
   - この見本から：`main.js`
3. 左の「サービス」の「＋」から **Drive API** を追加する（識別子は `Drive`、版は `v3`）。
4. 「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにし、`appsscript.json` をこの見本のものに置き換える。
5. スプレッドシートを開き直すと、メニューに「帳票」が出る。「帳票 → 設定と表を用意する」を実行する。
6. 「設定」シートの「失敗の通知先」を、失敗を知らせる先のアドレスに変える。

### clasp で送る

```bash
cd examples/pdf-batch
echo '{"scriptId":"（スプレッドシートに付いたスクリプトの ID）"}' > .clasp.json
cd ../..
npm run example:build -- pdf-batch
cd dist/pdf-batch
npx @google/clasp push
```

`appsscript.json` に Drive API（v3）を使う設定が入っているので、clasp で送るときは、エディタでサービスを足す手順は要りません。

## 使い方

- **見本で試す**：「見本のデータを入れる」（架空の 30 件）→「PDF を作る」。「明細」か「作成記録」にデータがあるときは、見本のデータは入れません。
- **本番**：「明細」に表を入れて「PDF を作る」。作成記録にある見積番号は飛ばします。
- **作り直す**：「作成記録」のその行を消し、フォルダの PDF もゴミ箱に入れてから「PDF を作る」。PDF が残っていると、同じ名前のファイルがあるので作らず、作成記録だけを戻します（上書きはしません）。
- **途中でやめる**：「作成を途中でやめる」。続きのトリガーと進み具合が消えます。作った PDF と作成記録は残り、もう一度「PDF を作る」で残りを作ります。
- **点検する**：「点検する」。スキーマの版・設定の値・明細の見出しを確かめ、直すことを並べます（直しはしません）。

## 設定（「設定」シート）

| 項目 | 既定の値 | 内容 |
|------|----------|------|
| 明細のシート／作成記録のシート／実行記録のシート | 明細／作成記録／実行記録 | シートの名前 |
| 帳票の題 | お見積書 | PDF の題とファイル名の頭 |
| 発行元 | 見本商事株式会社（架空） | PDF の右下に出る |
| PDF のフォルダ名 | 見本 お見積書 PDF（wi-t-gas-kit） | スクリプトが作るフォルダの名前。作ったあとに変えても、作り直しはしない |
| 1 回の上限（ミリ秒） | 270000 | 越える前に区切って続きを動かす（1〜360000） |
| 失敗の通知先 | ops@example.com | **必ず変える** |
| 列：見積番号〜列：日付 | 見積番号・宛先・品名・数量・単価・日付 | 明細の見出しの名前。先方の表の見出しに合わせる |

- 値がおかしいとき（通知先がメールアドレスでない、など）は、画面に「「設定」シートの「失敗の通知先」の値がメールアドレスになっていません。」のように知らせて、何もしません。通知先そのものが設定にあるので、メールでは知らせません。
- 設定シートは、コードを入れ替えても消えません。版上げで項目が増えたときは、「設定と表を用意する」が足りない項目だけを足します。

## 権限

| 権限 | 理由 |
|------|------|
| `https://www.googleapis.com/auth/spreadsheets.currentonly` | このスプレッドシートの設定・明細・作成記録・実行記録を読み書きする |
| `https://www.googleapis.com/auth/drive.file` | PDF を置くフォルダと PDF を作る。このスクリプトが作ったフォルダとファイルにだけ触れる |
| `https://www.googleapis.com/auth/script.scriptapp` | 件数が多いときの続きのトリガーを作る・消す。引き継ぎ書にトリガーを書く |
| `https://www.googleapis.com/auth/script.send_mail` | 失敗をメールで知らせる |
| `https://www.googleapis.com/auth/script.container.ui` | メニューと知らせを出す |

- ドライブへの保存は、`DriveApp` ではなく **Drive API（詳細サービス v3）** を使います。2026-11-27 の実機確認（P0）で、`DriveApp` は `drive.file` の権限ではフォルダも作れない（`drive` の権限を求められる）と分かったためです。Drive API なら `drive.file` だけでフォルダと PDF を作れ、名前で探せました。
- PDF は HTML から作ります（`Utilities.newBlob(html, 'text/html').getAs('application/pdf')`）。ドキュメントの権限も、外部への取得の権限も使いません。

## できないこと

- **先方が手で作ったフォルダを出力先にはできません。** `drive.file` では、このスクリプトが作ったフォルダとファイルしか見えないためです。PDF はスクリプトが作ったフォルダに置き、要るなら先方がそこから移してください。
- 1 枚に載る品名は 1 行です（明細の 1 行が 1 枚）。
- 体裁は HTML と CSS で作る簡素なものです。2026-11-27 の実機確認（P0）では、崩れは見つかりませんでした。会社の書式に合わせるときは、`main.js` の `pdfBatchRender_` の HTML を直します。

## 時間の目安

- 2026-11-27 の実機確認（P0）では、HTML から PDF にして保存するまでが、1 件あたり 1.3〜1.9 秒でした（確認用の短い帳票 5 件）。この見本そのものの 30 件の時間は、確認項目 A2 で測ってから書きます。
- 1 回の実行が「1 回の上限」を越えそうになると区切り、続きは 1 分ほどあと（実機では 65〜94 秒後）に動きます。

## 業務データの扱い

- 「作成記録」には見積番号とファイル名が入ります。PDF には宛先・品名・金額が入ります。スプレッドシートとフォルダの共有の範囲に気をつけてください。
- 「実行記録」とメールに書くのは、件数（作成・作成済み・番号なし・不備）とエラー種別だけです。

## 失敗したとき

| 起きたこと | 画面 | 実行記録 | メール |
|------------|------|----------|--------|
| 設定と表をまだ用意していない（版上げの途中を含む） | 「設定と表を用意する」を実行するよう知らせる | 残さない | 送らない |
| 設定の値がおかしい | どの項目かを知らせる | 残さない | 送らない（通知先も設定のため） |
| 明細が空 | 明細を入れるよう知らせる | 残さない | 送らない |
| 明細の見出しが足りない | どの列がないかを知らせる | 失敗（`SheetFormatError`） | 送る |
| PDF の保存などで失敗した | Apps Script のエラー表示 | 失敗（エラー種別） | 送る |

失敗した帳票は作成記録に残らないので、もう一度「PDF を作る」で、その帳票から作ります。数量・単価が数として読めない行と、見積番号が空の行は作らずに数え、実行記録のメッセージに「不備」「番号なし」の件数を出します。

## 版上げのしかた

1. **事前**：スプレッドシートをコピーする（「ファイル → コピーを作成」）。スクリプトもいっしょにコピーされます。
2. **入れ替え**：新しい版の `main.js` と、`parts.json` の部品を貼り直す（clasp なら `npm run example:build -- pdf-batch` のあと `clasp push`）。`appsscript.json` も新しい版のものにする。
3. **実行**：メニュー「帳票 → 設定と表を用意する」。まだ動いていない移行の段だけが動き、スキーマの版が上がります。何度動かしても結果は変わりません。設定シートの値は残ります。
4. **点検**：「点検する」で問題がないことを確かめ、「引き継ぎ書を作る」で版が新しくなったことを確かめる。
5. **戻し方**：うまくいかないときは、1 で作ったコピーを使う（元のスプレッドシートは使うのをやめる）。続きのトリガーが残っていれば、元のほうのトリガーの画面で消す。

`CHANGELOG.md` に、版ごとに何が変わり、移行の段があるかを書きます。

## 止め方

- 作成の途中なら「作成を途中でやめる」。トリガーの画面で `runPdfBatch` のトリガーが残っていないことを確かめる。
- メニューを出さないようにするなら、`main.js` の `onOpen` を消す。
- 作った PDF はドライブのフォルダに残ります。要らなければフォルダごと消してください。
- すでに `onOpen` がある場合は、この見本の `onOpen` の中身（メニューを足す部分）を、今ある `onOpen` に移してください。
