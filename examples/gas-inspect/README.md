# 見本：GAS の点検（gas-inspect）

[English](README.en.md)

先方がすでに使っている GAS のプロジェクトに、ファイルを 1 つだけ足して点検する見本です。トリガー・権限・6 分の上限・失敗の記録を見て、結果を「点検結果」シートに、版・トリガー・権限・プロパティ（値は伏せる）・シートの構成を「引き継ぎ書」シートに書きます。点検が終わったら、足したものを外して元に戻します。

- 版：`1.0.0`（`main.js` の `GAS_INSPECT_VERSION`。変更の記録は [CHANGELOG.md](CHANGELOG.md)）
- 使う部品：`version.js`・`handover.js`（`parts.json`）。部品は点検のファイルの中に閉じ込め、先方のグローバルの `WitGas` には触りません。
- 足すファイル：`wit-inspect.js`（`npm run example:build -- gas-inspect` で `dist/gas-inspect/` にできる 1 つのファイル）

## 点検する前に：先方の了解を得る

**点検のファイルも、点検のための権限も、先方の了解を得てから足してください。** 先方のプロジェクトに手を入れることになるためです。了解を得るときは、次のことを伝えます。

- 足すもの：ファイル 1 つ（`wit-inspect`）。`appsscript.json` に権限を書いているプロジェクトなら、権限を最大 2 つ（下の「権限」）。
- 権限が増えるので、実行するときに承認の画面が出ること。
- 書くもの：同じスプレッドシートの「点検結果」と「引き継ぎ書」の 2 つのシートだけ。先方のコード・トリガー・プロパティ・ほかのシートは変えないこと。
- 読むもの：関数の名前と中身（点検に使うだけで、どこにも書かない）、トリガーの一覧、承認済みの権限、タイムゾーン、シートの名前と行数・列数、プロパティのキー（値は書かない）。
- 終わったら、ファイルと権限を外して元に戻すこと。戻したかどうかを「点検結果」の最後の行（「後片付け：元に戻したか」）に残すこと。

## 点検のしかた

1. **控えを取る**：先方のプロジェクトで「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにし、今の `appsscript.json` の中身をすべて控える（メモ帳などに貼る）。オンにしたことも控える。
2. **ファイルを足す**：「ファイル → ＋ → スクリプト」で `wit-inspect` という名前のファイルを作り、`dist/gas-inspect/wit-inspect.js` の中身を貼る。ほかのファイルは触らない。
3. **権限を足す（`oauthScopes` があるときだけ）**：`appsscript.json` に `oauthScopes` があれば、次の 2 つのうち、まだないものだけを足す。何を足したかを控える。`oauthScopes` がなければ足さない（GAS がコードから推し量り、承認の画面に出る）。
   - `https://www.googleapis.com/auth/script.scriptapp`
   - `https://www.googleapis.com/auth/spreadsheets.currentonly`
4. **実行する**：エディタの上で関数 `witInspect` を選び、「実行」。承認の画面が出たら、中身を先方と確かめてから許可する。
   - トリガーは、実行した人が作ったものだけが見えます。**トリガーを作った人（ふつうは先方の担当者）に実行してもらってください**。
5. **結果を見る**：スプレッドシートの「点検結果」と「引き継ぎ書」を、先方と一緒に見る。
6. **後片付け（元に戻す）**：
   1. `wit-inspect` のファイルを消す。
   2. `appsscript.json` を、1 で控えた中身に貼り直す（3 で足した権限が消える）。1 でマニフェストの表示をオンにしたなら、オフに戻す。
   3. エディタの「概要」の「プロジェクトの OAuth スコープ」に、3 で足した権限が出ていないことを見る。
   4. 先方の処理を 1 回動かして（またはトリガーの次の実行を待って）、いつもどおり動くことを先方と確かめる。
7. **「元に戻したか」を残す**：「点検結果」の最後の行「後片付け：元に戻したか」の「確認」の欄に、「済み」と日付を書く。「点検結果」と「引き継ぎ書」のシートは記録として残す（要らなければ先方が消す）。

スプレッドシートに付いていないスクリプト（スタンドアロン）では、シートを開く権限を足さないため、点検結果をエディタの実行ログに出し、引き継ぎ書は作りません。

## 点検すること

「点検結果」の「状態」は 4 つです：**直したほうがよい**・**気をつける**・**目で確かめる**（この点検では読めないので、画面で見る）・**よい**。いちばん上の「まとめ」に、それぞれの件数が出ます。

| 項目 | 見ること | 状態 |
|------|----------|------|
| 関数 | 見つけた先方の関数の名前（点検のファイルの関数は除く） | よい |
| トリガーの数 | 1 人・1 スクリプトあたり 20 個までのうち、いくつ使っているか | 15 個以上で「気をつける」 |
| トリガー：関数名 | 動かす関数が見つからない（消した・名前を変えた） | 直したほうがよい |
| | 同じ関数・同じ種類・同じ起動元のトリガーが 2 つ以上（フォームの送信時など） | 直したほうがよい（1 回のできごとで 2 回動く） |
| | 時間主導型が同じ関数に 2 つ以上 | 気をつける（時刻がちがえば意図どおりのこともある） |
| | インストール型のトリガーの関数名が `onOpen`・`onEdit` など | 直したほうがよい（シンプルトリガーとしても動き、二重に動く） |
| 動き終わったトリガー | 時間主導型があるとき。1 回だけのトリガーは動き終わっても「無効」で残り、一覧からは見分けられない | 目で確かめる |
| 二重実行：関数名 | 時間主導型・フォームの送信時・編集時などで動く関数（と、そこから呼んでいる関数）に、ロック（`LockService`・`WitGas.lock`・`WitGas.guard`）があるか | ないと「気をつける」 |
| 失敗の扱い：関数名 | トリガーで動く関数が、失敗をつかまえているか。つかまえていて、知らせも投げ直しもしていないか | どちらも「気をつける」 |
| ウェブアプリ | `doGet`・`doPost` があるか（公開の設定を見る） | 目で確かめる |
| 承認済みの権限 | 承認済みの権限を一つずつ。広い権限（ドライブ全体・Gmail 全体・スプレッドシート全体など）には、代わりに使えることが多い狭い権限を書く | 広いものは「気をつける」 |
| タイムゾーン | スクリプトとスプレッドシートのタイムゾーンが同じか | 違えば「気をつける」 |
| 部品集 WitGas | 先方に WitGas の部品が入っていれば、部品の版がそろっているか | そろっていなければ「気をつける」 |
| 6 分の上限 | この点検では実行の時間を読めない。「実行数」の画面で見る手順を書く | 目で確かめる |
| 権限を appsscript.json に書いているか | この点検では `appsscript.json` を読めない。見る場所を書く | 目で確かめる |
| 引き継ぎ書 | 「引き継ぎ書」シートを書けたか | 書けなければ「目で確かめる」 |
| 後片付け：元に戻したか | 点検のあとに、足したファイルと権限を外したか。「確認」の欄に「済み」と日付を書く | 目で確かめる |

### できないこと（この版の限り）

- 関数の中身は文字として探しているだけです（ロックや `catch` の言葉があるか）。動かしてみて確かめてはいません。`catch` の中身が正しいかは、人が読んで確かめます。
- 探せるのは、グローバルに置いた関数（`function 名前() {}` で書いたもの）です。`const 名前 = () => {}` のように書いた関数や、ライブラリの中の関数は探せないことがあります。
- ほかの人が作ったトリガー、実行の時間、`appsscript.json` の中身は読みません（読むには、もっと広い権限か Apps Script API が要るため）。

## 書くもの・書かないもの

- 書くのは「点検結果」と「引き継ぎ書」のシートだけです。同じ名前で別の中身のシートがあれば、書かずに止めます（「点検結果」がそうなら何も書かず、「引き継ぎ書」がそうなら点検結果だけを書きます）。
- 書くのは関数名・トリガーの種類・件数・権限・タイムゾーン・シートの名前と行数・列数・プロパティのキーまでです。**関数の中身（コード）・シートの値・プロパティの値は書きません。**
- 引き継ぎ書の「権限」の理由は「（理由が書かれていない）」になります。点検のあとで、先方と一緒に理由を書き足してください。
- トリガーを作る・消す、プロパティを書く、メールを送る、ことはしません。

## 権限

点検のために足すことがある権限は、この 2 つだけです（`appsscript.json` に書いてある 2 つ）。先方の `appsscript.json` を、この見本の `appsscript.json` に置き換えないでください。足すのは、ないものだけです。

| 権限 | 使う理由 |
|------|----------|
| `script.scriptapp` | トリガーの一覧と、承認済みの権限を読むため |
| `spreadsheets.currentonly` | 同じスプレッドシートの「点検結果」と「引き継ぎ書」に書くため |

## この見本の段階

| 段階 | この見本でできること |
|------|----------------------|
| 1. 動く | エディタから `witInspect` を 1 回動かすと、点検結果と引き継ぎ書が出る |
| 3. 変えられる | 引き継ぎ書を作る。版上げは、ファイルを新しい版に入れ替えるだけ（下の「設定と版上げ」） |

- この見本は、点検のときだけ人が動かすもので、定時には動かしません（段階 2 はありません）。
- **`WitGas.guard` で包んでいません。** 先方のスクリプトのロックを取ると、先方の処理を止めたり、飛ばさせたりするおそれがあるためです。また、メールも送りません（通知のための権限を増やさないため）。失敗したときは、動かした人のエディタにエラーが出ます。実行の記録は「点検結果」のシート（いちばん上に点検した日時）です。

### 次の段階で足せること

- 実行の時間を読む（「実行数」と同じ中身）。Apps Script API と広い権限が要るので、先方の了解を別に得る。
- `appsscript.json` の中身を読み、`oauthScopes` の有無と、書いてある権限と承認済みの権限の違いを出す（同じく Apps Script API）。
- 前の点検との違い（直したもの・増えたもの）を出す。
- スタンドアロンのスクリプトでも、点検結果を新しいスプレッドシートに書く（ファイルを作る権限が増える）。

## 設定と版上げ

- 設定シートと `migrate()` は持ちません。先方ごとに変える値がなく、点検のファイルは点検のたびに足して外すためです。
- 版上げは、`wit-inspect` のファイルの中身を新しい版のものに入れ替えるだけです。「点検結果」のシートは毎回書き直します。
- 版は「点検結果」の 2 行目（`gas-inspect 1.0.0`）に出ます。

## テスト

`test/examples/gas-inspect.test.js` で、ビルドしたファイル（`wit-inspect.js`）を、架空の先方のプロジェクトと一緒に読み込んで確かめています。足すグローバルの名前が 2 つだけで、先方の `WitGas` を変えないこと、トリガーを作らず消さないこと、関数の中身とシートの値を書かないことも確かめています。
