# 見本：フォーム → 承認 → 通知（form-approval）

[English](README.en.md)

Google フォームで受けた申請を、承認者がスプレッドシートで「承認」か「差し戻し」に選び、その結果を申請者にメールで知らせる見本です。10 分ごとに自動で動きます。

- 版：`1.0.0`（`main.js` の `FORM_APPROVAL_VERSION`。変更の記録は [CHANGELOG.md](CHANGELOG.md)）
- 使う部品：`version.js`・`lock.js`・`runlog.js`・`notify.js`・`guard.js`・`handover.js`・`settings.js`・`migrate.js`（`parts.json`）
- データはすべて架空です。

## 流れ

1. 申請者がフォームに答える。フォームの「メールアドレスを収集する」で、申請者のアドレスが回答のシート（「フォームの回答 1」）に入る。
2. 10 分ごとに、このスクリプトが回答のシートの新しい回答を「承認」シートに取り込み、申請番号（`A-0001` など）を振って「未判断」にする。承認者には「新しい申請 2 件（判断待ち 5 件）」のように、**件数だけ**をメールで知らせる。
3. 承認者が「承認」シートの「判断」で「承認」か「差し戻し」を選ぶ。差し戻しのときは「コメント」に理由を書く。
4. 次の回（最大 10 分後）に、申請者へ結果をメールで知らせ、「状態」を「知らせた（承認）」などにする。一度知らせた申請には、二度と送らない。

- フォームそのものは読みません（フォームの権限を持ちません）。読むのは、フォームがつながった回答のシートだけです。
- 判断の取り込みは、時間主導型のトリガー（10 分ごと）で行います。編集のたびに動くトリガー（`onEdit`）は使いません。編集のたびに動かないようにするためと、選び間違えてすぐ直したときに、送る前に間に合うことがあるためです（間に合うのは、次の回が動く前に直したときだけです）。

## この見本の段階

| 段階 | この見本でできること |
|------|----------------------|
| 1. 動く | メニューの「今すぐ取り込む・知らせる」で、取り込みと知らせを 1 回動かす。二重に動かない・実行記録・失敗の通知（`WitGas.guard`） |
| 2. 任せられる | 10 分ごとに自動で動く。1 回に知らせる数と時間（4.5 分）の上限を越えず、残りは次の回に送る。「点検する」で、回答のシートと承認のシートを突き合わせる（取り込み漏れ・消えた回答・送信中のまま・知らせたあとの変更） |
| 3. 変えられる | シート名・列名・写す列・通知先・メールの文・上限を「設定」シートで変えられる。引き継ぎ書と版上げの手順がある |

### 次の段階で足せること

- 承認を 2 段にする（課長 → 部長）。金額で承認者を分ける。
- 判断した人を残す（今は、誰が選んだかを残しません。シートの変更履歴で見ます）。
- 判断待ちが長いものを、毎朝まとめて承認者に知らせる。
- 承認したものを、ほかの表（台帳・会計）に写す。

## シート

| シート | 中身 | 誰が書くか |
|--------|------|------------|
| フォームの回答 1 | フォームの回答（タイムスタンプ・メールアドレス・質問の答え） | フォーム |
| 承認 | 1 行が 1 件の申請。申請番号・受付日時・申請者・判断・コメント・状態・知らせた日時・回答の行と、写す列 | このスクリプト（判断とコメントは承認者） |
| 設定 | 先方ごとに変える値（下の「設定」） | 「設定と表を用意する」が作り、先方が値を変える |
| 実行記録 | 1 実行 1 行（件数と内訳だけ） | このスクリプト |
| 引き継ぎ書 | 版・トリガー・権限・設定値・止め方 | 「引き継ぎ書を作る」 |

**回答のシートの行は消さず、並べ替えないでください。** 取り込み済みかどうかを、タイムスタンプとメールアドレスで見分けているためです（消したり並べ替えたりすると「点検する」で知らせます）。承認のシートの行も消さないでください（申請番号は行の数から振ります）。

## 入れ方

1. フォームを作り、「設定 → 回答 → メールアドレスを収集する」をオンにする。
2. フォームの「回答」→「スプレッドシートにリンク」で、新しいスプレッドシートを作る（「フォームの回答 1」シートができる）。
3. そのスプレッドシートで「拡張機能 → Apps Script」を開き、次のファイルを同じ名前で作って中身を貼る。
   - リポジトリの `src/` から、`parts.json` に書いてある 8 つ
   - この見本から：`main.js`
4. 「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにし、`appsscript.json` をこの見本のものに置き換える。
5. スプレッドシートを開き直すと、メニューに「申請」が出る。「申請 → 設定と表を用意する」を実行する。
6. 「設定」シートの「承認者の通知先」と「失敗の通知先」を変える。フォームの質問に合わせて「写す列」を変える。
7. 「点検する」で問題がないことを確かめ、「定時の動きを始める（10 分ごと）」を実行する。

clasp で送るときは：

```bash
cd examples/form-approval
echo '{"scriptId":"（スプレッドシートに付いたスクリプトの ID）"}' > .clasp.json
cd ../..
npm run example:build -- form-approval
cd dist/form-approval
npx @google/clasp push
```

フォームがまだないときは、「見本のデータを入れる」で、架空の回答 3 件が入った「フォームの回答 1」シートを作って試せます（宛先は `example.com` の架空のアドレスなので、判断を選ぶ前に自分のアドレスに書き換えてください）。

## 使い方

- **承認者**：メールが届いたら「承認」シートを開き、「判断」で「承認」か「差し戻し」を選ぶ。差し戻しのときは「コメント」に理由を書く。選んでから最大 10 分で申請者に届く。**迷うときは「判断」を空のままにする**（コメントに書いておくのはかまわない）。
- **差し戻されたとき**：申請者はフォームからもう一度申請する（新しい申請番号になる）。
- **今すぐ動かす**：「今すぐ取り込む・知らせる」。
- **止める**：「定時の動きを止める」。シートの中身は残る。
- **点検する**：「点検する」。直すことを並べます（直しはしません）。

## 設定（「設定」シート）

| 項目 | 既定の値 | 内容 |
|------|----------|------|
| 回答のシート／承認のシート／実行記録のシート | フォームの回答 1／承認／実行記録 | シートの名前 |
| 列：タイムスタンプ／列：メールアドレス | タイムスタンプ／メールアドレス | 回答のシートの見出しの名前 |
| 写す列 | 件名, 金額 | 承認のシートに写す、回答のシートの見出し（カンマで区切る）。承認者が判断に使う |
| 申請番号の頭 | A- | `A-0001` のように振る |
| 承認者の通知先 | approver@example.com | **必ず変える**。複数ならカンマで区切る |
| 失敗の通知先 | ops@example.com | **必ず変える** |
| 件名の頭 | [申請] | メールの件名の頭 |
| 送り主の名前 | 申請の受付 | 申請者に届くメールの差出人の名前 |
| 返信先 | （空） | 申請者が返信したときの宛先。空なら、トリガーを作った人 |
| 承認のメールの文／差し戻しのメールの文 | （見本の文） | `{申請番号}`・`{受付日時}`・`{結果}`・`{コメント}` が差し込まれる。コメントが空なら「（なし）」 |
| 1 回に知らせる上限 | 50 | 1 回の実行で申請者に送るメールの数（1〜100）。残りは次の回 |

- 値がおかしいときは、画面に「「設定」シートの「失敗の通知先」の値がメールアドレスになっていません。」のように知らせて、何もしません。
- **定時に動いているとき（画面がない）は、「失敗の通知先」だけでも読めれば、そこにメールで知らせます**（1 時間に 1 通まで）。10 分ごとに動くので、画面がないと気づけないためです。
- 設定シートは、コードを入れ替えても消えません。

## 権限

| 権限 | 理由 |
|------|------|
| `https://www.googleapis.com/auth/spreadsheets.currentonly` | このスプレッドシートの回答・承認・設定・実行記録を読み書きする |
| `https://www.googleapis.com/auth/script.scriptapp` | 10 分ごとのトリガーを作る・消す。引き継ぎ書にトリガーを書く |
| `https://www.googleapis.com/auth/script.send_mail` | 承認者と申請者に知らせる。失敗を知らせる |
| `https://www.googleapis.com/auth/script.container.ui` | メニューと知らせを出す |

フォームの権限（`forms`）は使いません。メールは `MailApp` で送るので、Gmail を読む権限も使いません。

## 二度送らない・送り漏らさないための書き方

- 送る前に「状態」を「送信中」にして書き込みを確定し（`SpreadsheetApp.flush()`）、送れたら「知らせた（承認）」などにします。
- 送信の途中で止まった（失敗した・時間切れになった）ときは「送信中」のまま残り、次の回も**送り直しません**（二度送るより、送ったかを人が確かめるほうを選んでいます）。「点検する」が「「送信中」のままの申請が 1 件」と知らせます。トリガーを作った人の Gmail の「送信済み」で届いたかを確かめ、送っていなければ「状態」を「未判断」に戻すと、次の回に送ります。
- 知らせたあとに「判断」を変えても、もう一度は送りません（「点検する」で知らせます）。
- 1 回の実行は、知らせる数が「1 回に知らせる上限」に届くか、4.5 分を越えそうになるか、1 日の送信の残り（`MailApp.getRemainingDailyQuota()`）がなくなったら、残りを次の回にまわします。
- 二重に動かないよう、`WitGas.guard` で包んでいます（メニューから動かしたときと、トリガーが重なったときは、あとのほうが「スキップ」になる）。

## 1 日に送れる数

`MailApp` で 1 日に送れる宛先の数には、アカウントの種類ごとの上限があります（Google の Apps Script の説明の「割り当て」を見てください）。この見本では、承認者への 1 通と、申請者への 1 件 1 通を数えます。上限に近づいたら残りを次の日にまわし、「実行記録」の「次の回へ」に件数が出ます。

## 業務データの扱い

- 「承認」シートには、申請者のアドレスと「写す列」の値が入ります。スプレッドシートの共有の範囲に気をつけてください。
- 申請者へのメールには、申請番号・受付日時・結果・コメントが入ります（申請者への知らせそのものなので）。
- 承認者へのメールに書くのは、件数とスプレッドシートの URL だけです。
- 「実行記録」と失敗の通知に書くのは、件数（取り込み・知らせた・宛先なし・次の回へ・送信中のまま）とエラー種別だけです。
- フォームの答えが `=` などで始まっていても、承認のシートには文字として写します（式として動かないように）。

## 失敗したとき

| 起きたこと | 画面 | 実行記録 | メール |
|------------|------|----------|--------|
| 設定と表をまだ用意していない | 「設定と表を用意する」を実行するよう知らせる | 残さない | 送らない |
| 設定の値がおかしい | どの項目かを知らせる | 残さない | 画面がない（定時）ときだけ、失敗の通知先に送る |
| 回答のシートがない・見出しが足りない | どのシート・列がないかを知らせる | 失敗（`SheetFormatError`） | 失敗の通知先に送る |
| メールが送れなかったなど | Apps Script のエラー表示 | 失敗（エラー種別） | 失敗の通知先に送る |
| 宛先がメールアドレスでない | — | 「宛先なし」の件数 | 送らない（状態を「宛先なし（知らせていない）」にする） |

## 版上げのしかた

1. **事前**：スプレッドシートをコピーする（「ファイル → コピーを作成」）。スクリプトもいっしょにコピーされます。トリガーはコピーされません。つながったフォームもいっしょにコピーされることがあるので、コピーのほうのフォームは配らず、コピーは戻すときのためだけに使います（実機確認 F9 で確かめる）。
2. **止める**：「定時の動きを止める」。
3. **入れ替え**：新しい版の `main.js` と、`parts.json` の部品を貼り直す（clasp なら `npm run example:build -- form-approval` のあと `clasp push`）。`appsscript.json` も新しい版のものにする。
4. **実行**：「設定と表を用意する」。まだ動いていない移行の段だけが動き、スキーマの版が上がります。何度動かしても結果は変わりません。設定シートの値は残ります。
5. **点検**：「点検する」で問題がないことを確かめ、「引き継ぎ書を作る」で版が新しくなったことを確かめる。
6. **始める**：「定時の動きを始める」。
7. **戻し方**：うまくいかないときは、止めたまま、1 で作ったコピーの「承認」シートと「設定」シートの中身を元のスプレッドシートに貼り戻し、前の版のファイルを貼り直す。元のスプレッドシートにはフォームがつながっているので、スプレッドシートごと取り替えないでください。

`CHANGELOG.md` に、版ごとに何が変わり、移行の段があるかを書きます。

## 止め方

- 「定時の動きを止める」（トリガーを作った人が実行する）。トリガーの画面で `runFormApproval` のトリガーが残っていないことを確かめる。
- 申請の受付もやめるなら、フォームの「回答」で「回答を受け付ける」をオフにする。
- メニューを出さないようにするなら、`main.js` の `onOpen` を消す。すでに `onOpen` がある場合は、この見本の `onOpen` の中身（メニューを足す部分）を、今ある `onOpen` に移してください。
