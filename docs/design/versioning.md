# 設計メモ：版・設定・データの形の移行

CLAUDE.md の「版の約束」を満たすために、部品の側に何を置いたかと、その理由。

## 部品の版（`WitGas.version` と各部品の `VERSION`）

- 部品集の版は `package.json` の `version`。Git のタグ `v0.x.y` と GitHub のリリースで出す。
- `src/version.js` が `WitGas.version` を、各部品が `VERSION` を持つ。どれも同じ番号にする（テスト `test/migrate.test.js` で、`package.json` と同じか確かめる）。
- **理由**：先方には、部品を「ファイルのコピー」で入れる。ファイルを入れ替えたときに 1 つだけ古いまま残ることがある。部品ごとに版を持たせると、`WitGas.handover` の「版」の欄で、部品集の版と違う部品に印をつけて気づける。
- 版を上げるときは、変えていない部品も含めて、すべての `VERSION` を新しい番号にする（「その版の部品集から取ったファイル」という意味にする）。

## 設定（`WitGas.settings`）

- 「設定」シート（項目・値・説明）を読み書きする。`ensure` は足りない項目だけを足し、今ある値は書き換えない。`read` は型（文字・数・はい/いいえ・メールアドレス）に合わせて読み、合わなければ `SettingsError`（項目名だけを書き、値は書かない）。
- **部品にした理由**：9 本の見本のどれも「先方ごとに変える値」を持つ。見本ごとに書くと、同じ読み書きと検査を 9 回書くことになり、直すときに漏れる。
- **シートにした理由**：スクリプトのプロパティは、先方がエディタを開かないと見られない。シートなら、コードを触らずに変えられる（段階 3「変えられる」）。秘密の値（鍵など）はシートに置かず、スクリプトのプロパティに置く。

## データの形の移行（`WitGas.migrate`）

- 段（`{version, name, run}`）を 1, 2, 3 … の順に並べ、スクリプトのプロパティ `WitGas.schema:<key>` の版より新しい段だけを動かす。1 段ごとに版を保存する。
- 段は、何度動かしても結果が変わらない書き方にする（シートがなければ作る、列がなければ足す、など）。途中で止まっても、もう一度 `run` すれば続きから動く。
- データの形がコードより新しいとき（古いコードに戻したとき）は、触らずにエラーにする。
- **部品にした理由**：「済んだ段を飛ばす」「1 段ごとに保存する」「新しすぎるときに止める」は、どの見本でも同じで、間違えると先方のデータを壊す。見本ごとに書かず、テストした 1 つを使う。段の中身（何をどう直すか）は見本ごとに `main.js` に書く。
- 二重に動かないように、見本では `WitGas.guard` で包んで呼ぶ。

## 配り方

- ファイルのコピーを基本にする（`npm run example:build -- <名前>` でまとめたものを、先方のアカウントのスクリプトに入れる）。
- GAS のライブラリの形は、先方が自分のアカウントに置く場合に限る。当社のアカウントから配ると、先方が当社のアカウントに頼ることになり、「持ち主と権限」の約束に反するため。
